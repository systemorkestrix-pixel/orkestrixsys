# Orkestrix Systems — تقرير التدقيق والتوافق

تاريخ التدقيق: 25 أغسطس 2026
النطاق: التطبيق الحالي في `apps/web` فقط. لم يُعدّل أي ملف برمجي أثناء هذا التدقيق.

## الملخص التنفيذي

الموقع يملك لغة بصرية متماسكة وفكرة واضحة عن بناء الأنظمة للأعمال، والصفحة الرئيسية والخدمات تشرحان الوعد والمنهج بصورة مقبولة. لكنه ليس نظامًا عامًا مغلقًا بعد: صفحة الأعمال ليست قائمة مشاريع فعلية، مسارات تفاصيل المشاريع غير موجودة، نموذج الطلب لا يحفظ أو يرسل أي بيانات، وصفحة «من نحن» غير موجودة. كما توجد بقايا تقنية من قالب سابق وبيانات SEO غير مكتملة.

الحكم النهائي: **READY FOR SECONDARY PAGE CLOSURE**.
لا ينتقل العمل إلى Project Details أو قاعدة البيانات أو لوحة الإدارة قبل إغلاق `/projects` وقرار مسار التحويل وربط `/contact` فعليًا.

## توافق العلامة والرسالة

**المصدر المعتمد:** Orkestrix Systems — Digital Systems for Businesses — «من الفكرة إلى التشغيل».

### ما يتوافق

- الصفحة الرئيسية تستخدم وعدًا قريبًا: «لديك فكرة… نحولها إلى نظام يعمل»، وتشرح رحلة العمل حتى التشغيل والدعم.
- الخدمات الخمس المطابقة للمصدر موجودة حصريًا: مواقع الأعمال، المتاجر الإلكترونية، لوحات الإدارة، الأنظمة المخصصة، والتكاملات والأتمتة.
- الأسلوب يتجنب البيع التقني المباشر غالبًا، ويعرض أثر النظام على النشاط.
- الألوان، الاتجاه RTL، التكوينات الشبكية، واللغة التحريرية متسقة عمومًا مع شخصية شركة أنظمة وليست معرض مطوّر فردي.

### الفروقات

- الرسالة الرسمية «من الفكرة إلى التشغيل» لا تظهر كمرساة موحدة في عنوان ومحتوى وبيانات كل صفحة؛ تظهر بدائل صحيحة المعنى لكن متفرقة.
- `/projects` لا يقدم «دليل القدرة من خلال المشاريع»، بل أمثلة اتجاهات عامة؛ لذا يفقد الموقع مرحلة **Proof** في الرحلة.
- يوجد تعارض قرار: المرجع المرفق يحدد CTA الأساسي «ابدأ مشروعك → `/contact`»، أما التنفيذ الحالي فيقدّم الاستكشاف أولًا ويجعل التواصل رابطًا هادئًا. كلاهما يمكن أن يكون صحيحًا، لكن لا يمكن اعتبارهما سياسة تحويل واحدة دون قرار صريح.

## تدقيق المحتوى والكثافة

| الصفحة | تقييم الكثافة | الملاحظة |
|---|---|---|
| الرئيسية | Acceptable | الرحلة ذات 12 مرحلة غنية لكنها تظل قابلة للمسح بسبب التفاعل والبطاقات. |
| الخدمات | Acceptable إلى Too Dense | تفاصيل الخدمات الخمس مفيدة، لكن العبارات الانتقالية عن «من الفكرة إلى التشغيل» تتكرر في الـHero، الملاحظة، التسليم، والـCTA. |
| الأعمال | Unnecessary كصفحة أعمال | لا تحتوي على مشروع أو حالة أو نتيجة أو رابط تفصيل. |
| التواصل | Acceptable بصريًا، غير كافٍ وظيفيًا | الحقول مناسبة كبداية طلب، لكن النجاح المعروض غير حقيقي. |

إذا حذفت الرئيسية نخسر تعريف العلامة والمنهج. إذا حذفت الخدمات نخسر تحويل الحاجة إلى نوع حل. إذا حذفت `/projects` حاليًا لا نخسر دليلًا فعليًا لأن الدليل غير منفذ؛ وهذه علامة أن وظيفتها غير مغلقة.

## تدقيق UX والتحويل

المسار المنفذ: `الرئيسية → الخدمات → المقارنة/التسليم → الأعمال → تواصل هادئ`.

**نقاط القوة:** بطاقات خدمات الرئيسية تقود إلى تفاصيل الخدمة المناسبة، وروابط الأقسام الداخلية موجودة، ورابط التواصل لم يعد يقطع الاستكشاف مبكرًا.

**الاحتكاك:**

1. يصل المستخدم إلى `/projects` متوقعًا إثباتًا أو حالات، فيجد ثلاثة اتجاهات عامة فقط؛ لا توجد بطاقة مشروع أو حالة أو نتيجة.
2. لا توجد رحلة من مشروع إلى `/projects/[slug]` لأن المسار والبيانات غير موجودين.
3. إرسال نموذج `/contact` يغير الحالة محليًا إلى رسالة نجاح فقط؛ لا توجد عملية طلب أو تأهيل أو محادثة فعلية.
4. سياسة CTA غير محسومة بين المرجع الرسمي والتنفيذ الحالي.

## التدقيق البصري

الأساس البصري جيد: كحلي وأزرق وسماوي، حدود رفيعة، مساحات واسعة، ورسوم واجهات CSS بدل صور stock. جرى جعل Hero الخدمات كامل العرض وداكنًا لتمييز الصفحة الثانوية.

النقاط المفتوحة:

- توجد قواعد CSS واسعة خاصة بصفحات المشاريع وتفاصيل المشاريع (`.projects-page` و`.project-detail-page`) بلا مكوّن يستخدمها؛ وهذا يخلق فجوة بين التصميم المجهز والتجربة الفعلية.
- صفحة الأعمال الحالية تستعمل قالب `DestinationPage` نفسه المستعمل للتواصل، فتفقد شخصيتها البصرية والوظيفية المستقلة.
- قواعد modal قديمة ما زالت في CSS بعد إزالة النموذج من الرئيسية؛ لا تؤثر مرئيًا لكنها دليل على تنظيف غير مكتمل.

## التدقيق التقني

| البند | النتيجة |
|---|---|
| `pnpm typecheck` | ناجح في آخر تحقق |
| `pnpm build` | ناجح في آخر تحقق |
| الاستجابة | توجد نقاط توقف لـ900px و640px؛ لم يجر اختبار تفاعلي حقيقي على أجهزة فعلية في هذا التدقيق الثابت |
| الوصول | يوجد skip link، حالات `aria-expanded`، دعم focus، و`prefers-reduced-motion` |
| الأخطاء | Error Boundary يسجل أخطاء إلى console؛ لا توجد أخطاء بناء مسجلة |
| التوجيه | يدوي ولا يدعم 404 أو مسارات project details |
| البيانات | لا يوجد نموذج بيانات للمشاريع ولا طبقة حفظ لطلبات المشاريع |

### تنظيف تقني مطلوب لاحقًا

- نحو 50 مكوّن UI عام موجودة داخل `src/components/ui` دون ظهور استعمال مباشر لها في صفحات الموقع الحالية.
- `pages/not-found.tsx` و`hooks/use-mobile.tsx` و`hooks/use-toast.ts` تبدو غير مستعملة.
- حزم كثيرة في `apps/web/package.json` لا تدل imports الصفحات الحالية على استخدامها؛ يلزم تدقيق حزم منفصل قبل الحذف.
- CSS يتضمن قواعد للمودال ولـProjects/Project Details غير مرتبطة بالتنفيذ الحالي.

## التدقيق الملاحي وSEO

- الروابط الداخلية الموجودة تشير إلى `/`, `/services`, `/projects`, `/contact` أو أقسام موجودة؛ لا يظهر رابط عام مكسور في الفحص الثابت.
- لا يوجد `/about` رغم أنه في البنية المعتمدة، ولا يظهر في التنقل الحالي؛ هذا مقبول مؤقتًا فقط إذا اعتُبر مؤجلًا رسميًا.
- `robots.txt` يسمح بالفهرسة، وfavicon موجود.
- لا يوجد `sitemap.xml`.
- الصفحة الرئيسية لا تضبط canonical أو Open Graph URL ديناميكيًا، خلاف صفحات services/destination.
- `index.html` يعرّف `lang="en"` رغم أن الواجهة عربية، وقيم الوصف وOpen Graph في الملف تظهر بترميز عربي مشوه؛ هذه فجوة SEO فعلية.
- `usePageMeta` يضبط canonical إلى `https://orkestrix.site` للصفحات الثانوية، لكن لا يوجد تحقق من إعداد fallback على منصة النشر لمسارات SPA العميقة.

## التدقيق المحمول

الهيكل يوفر قائمة هاتفية وتحجيمًا خاصًا للـHero وبطاقات وشبكات الخدمات. المخاطر المفتوحة التي تحتاج اختبارًا يدويًا قبل الإغلاق:

- التكوينات البصرية ذات التموضع المطلق في Hero الرئيسية والخدمات تحتاج اختبارًا عند 320px و375px و430px، خصوصًا بعد جعل Hero الخدمات كامل العرض.
- القائمة المحمولة تحوي روابط `<a>` وأزرارًا؛ يلزم المرور بلوحة المفاتيح واختبار الإغلاق بعد الانتقال.
- نموذج التواصل يحتاج اختبار ترتيب التركيز ولوحة المفاتيح الافتراضية، بعد ربطه بوجهة حقيقية.

## سجل الفجوات

### GAP-001

- **Page:** Projects
- **Type:** Product / Architecture
- **Expected:** قائمة مشاريع أو حالات مختصرة تقود إلى `/projects/[slug]`.
- **Actual:** مكوّن عام يعرض ثلاثة اتجاهات فقط.
- **Impact:** لا توجد مرحلة Proof ولا استعداد فعلي لتفاصيل المشاريع.
- **Priority:** P0
- **Required Action:** إغلاق صفحة Projects ببيانات مشاريع وتسلسل Preview → Detail قبل بناء التفاصيل نفسها.

### GAP-002

- **Page:** Contact
- **Type:** Conversion / Technical
- **Expected:** Project Request ينتج عنه طلب قابل للتتبع والتأهيل.
- **Actual:** `preventDefault()` ثم `setSent(true)`؛ لا شبكة ولا تخزين.
- **Impact:** فقدان كل leads وإظهار وعد «وصلتنا الفكرة» غير صحيح.
- **Priority:** P0
- **Required Action:** اختيار قناة استقبال وملكية البيانات ثم بناء الإرسال والتحقق ورسالة نجاح حقيقية.

### GAP-003

- **Page:** Site architecture
- **Type:** Routing
- **Expected:** `/projects/[slug]` ومعالجة للمسارات غير المعروفة.
- **Actual:** ثلاثة مسارات فقط، وأي مسار آخر يعرض الرئيسية.
- **Impact:** لا يمكن الانتقال من Preview إلى Full Story، والروابط الخاطئة مضللة.
- **Priority:** P1
- **Required Action:** بعد إغلاق Projects، إضافة router ومسار 404 ومسار slug.

### GAP-004

- **Page:** CTA policy
- **Type:** Marketing alignment
- **Expected:** سياسة واحدة بين المصدر الرسمي والتنفيذ.
- **Actual:** المرجع يفرض CTA مباشرًا إلى `/contact`؛ التنفيذ الحالي يفضّل الاستكشاف ويؤخر التواصل.
- **Impact:** لا يمكن تقييم التحويل أو اعتماد النص النهائي بلا قرار.
- **Priority:** P1
- **Required Action:** اعتماد أحد المسارين صراحة: CTA مباشر أو CTA استكشافي مع نقطة تواصل نهائية.

### GAP-005

- **Page:** Homepage / SEO
- **Type:** Domain / Metadata
- **Expected:** لغة عربية، metadata سليمة، canonical وOpen Graph URL وsitemap.
- **Actual:** `lang="en"`، قيم عربية مشوهة في `index.html`، لا sitemap، ولا canonical للصفحة الرئيسية.
- **Impact:** فهرسة ومشاركة اجتماعية غير موثوقة.
- **Priority:** P1
- **Required Action:** تدقيق SEO مستقل قبل النشر؛ لا يغيّر إعداد النشر نفسه.

### GAP-006

- **Page:** About
- **Type:** Architecture
- **Expected:** مسار `/about` في البنية المستهدفة.
- **Actual:** غير منفذ وغير ظاهر في التنقل.
- **Impact:** غير مانع لإغلاق الصفحات الحالية إذا كان مؤجلًا رسميًا؛ مانع لإعلان اكتمال البنية العامة.
- **Priority:** P2
- **Required Action:** توثيق التأجيل أو إنشاؤه بعد إغلاق Projects وContact.

### GAP-007

- **Page:** Frontend hygiene
- **Type:** Technical
- **Expected:** لا قواعد أو مكوّنات ميتة مرتبطة بتجارب ملغاة.
- **Actual:** CSS للمودال وCSS صفحات مشاريع/تفاصيل غير مستخدمين، ومكتبة UI كبيرة دون استعمال ظاهر.
- **Impact:** عبء صيانة وتشويش على الإغلاق، دون أثر مباشر على المستخدم الآن.
- **Priority:** P2
- **Required Action:** تنظيف مخصص بعد تثبيت بنية Projects النهائية، لا قبلها.

## توصية الإغلاق

لا تبنِ قاعدة بيانات أو لوحة تحكم أو تفاصيل مشاريع قبل أن توجد صفحة Projects ذات Preview منظم وسياسة CTA معتمدة. يمكن اعتبار الرئيسية والخدمات **مغلقتين بشرط** إغلاق GAP-004 وGAP-005 وإجراء اختبار يدوي للهاتف. تبقى Projects وContact مفتوحتين.
